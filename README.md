# Auth contract example (iOS + Android)

One shared behavioural contract, two native implementations.

- `contracts/auth/scenarios.json` – core SDK behaviour contract.
- `contracts/consumers/<app>/*.json` – consumer-driven scenarios (see `.github/CODEOWNERS`: each consuming team owns its folder; failures block SDK PRs).
- `android/api/*.api` – public API signature dump; `gradle apiCheck` fails on unreviewed API changes ; iOS equivalent: `tools/ios_api.sh check|dump|breaking` (baseline `ios/api/AuthSDK.swiftinterface`, `swift-api-digester` for breaking-change classification).
- `fake-auth-server/server.js` – dependency-free Node fake token endpoint, scripted per scenario, records requests.
- `ios/` – Swift package: reference `AuthClient` + Swift Testing runner (one parameterized test case per scenario).
- `android/` – Kotlin/Gradle (JVM): reference `AuthClient` + JUnit 5 runner (one test per scenario).

The `AuthClient` classes are minimal stand-ins for the SDK module under test; the point is the test structure.

- `android-instrumented/` – Android host app + Espresso tests (L3b): SDK login screen, Activity recreation, cold start. Runs on an emulator; shares the core `AuthClient` source with `android/`.
- `ios-host/` – iOS host app (project generated by `xcodegen`) + XCUITest (L3b): SDK login screen, background/foreground, terminate and relaunch with Keychain persistence. Runs on a simulator.

## Run

Requirements: Node, Swift 6 toolchain, JDK 21, Gradle.

    ./run_all.sh      # L2: contracts on both platforms, JVM / macOS only, seconds

Additionally for SDK-native tests: Xcode + `xcodegen`, a booted Android emulator (`adb devices`).

    ./run_native.sh   # L3b: UI + lifecycle on emulator and simulator, ~1-2 min

Adding a scenario = editing `scenarios.json` only; both platforms pick it up, so a behavioural divergence fails one platform's CI job.

## Strategy, CI and tooling

- `docs/FINAL_DELIVERABLE.md` (main document), `docs/risk-matrix.md` (risk register R1–R15), `docs/slides.md` (Marp deck). Build PDFs: `/opt/anaconda3/bin/python3 tools/build_docs.py` (output in `docs/dist/`, git-ignored).
- `.github/workflows/` – `pr.yml` (fast PR gate, green on GitHub), `ui-native.yml` (nightly Espresso/XCUITest matrix), `release.yml` (RC tags; canary and previous-release jobs are stubs).
- `compat.yaml` + `tools/gen_matrix.py pr|rc` – OS/device/module/release matrices.
- `tools/retry_flag_flaky.sh` – retry once and flag pass-on-retry as FLAKY.
- `tools/ios_api.sh` – iOS public-API contract.
